# Sing-Box X 1.0.2

Следующая версия компактного ядра Forkop на upstream sing-box 1.14.2.
Выпуск объединяет исправления устойчивости, уменьшение удерживаемого состояния
uTLS и поддержку XHTTP поверх HTTP/1.1 и HTTP/2.

## XHTTP

- Добавлен клиент XHTTP с режимами auto, stream-one, stream-up и packet-up.
- Поддерживаются TLS/REALITY и отдельная download-ветвь через downloadSettings.
- Перенесён согласованный набор патчей podkop-engine v1.14.2-r12 вместе с
  последующими исправлениями, а не только первая реализация транспорта.
- Исправлены отмена и закрытие запросов, обработка ошибок upload/download,
  сброс соединений, восстановление после отказов и работа пула XMUX.
- Учтены таймауты, rotation соединений, ограничения frame/header и освобождение
  ресурсов завершённых сессий.
- Добавлено ожидание HTTP/2 SETTINGS перед использованием нового соединения:
  первая upload-запись больше не опережает объявление серверного лимита заголовков.
- Ядро объявляет возможности transport.xhttp, transport.xhttp.http1 и
  transport.xhttp.http2 в выводе version.
- HTTP/3 и QUIC-транспорты не включены; конфигурация, требующая исключительно
  HTTP/3, явно отвергается, в том числе на отдельной download-ветви.

## Восемь исправлений устойчивости

- Ограничена сборка QUIC ClientHello при sniffing, добавлены проверки CRYPTO
  frames. Это защита остающегося QUIC-сниффера, а не добавление QUIC-транспортов.
- Ошибка запроса gRPC-lite/HTTP2 освобождает заблокированную запись.
- Таймаут одного DoH-запроса не сбрасывает соединение, обслуживающее другие
  запросы; сохранено восстановление действительно зависшего транспорта.
- Перенесены проверки входных протокольных данных из upstream.
- Закрытие соединений выполняется вне общей блокировки: зависший Close
  не блокирует регистрацию других соединений.
- Изолированы panic сниффера и ограничено количество удерживаемых пакетов.
- Сообщения Clash logs форматируются только при наличии подписчиков.
- Ограничены объём логирования panic stack и его удержание в metadata соединений.

## Память uTLS

- Освобождается ненужное состояние uTLS после завершения handshake.
- Повторный handshake учитывает фактическое состояние соединения.
- Сохранено освобождение состояния uTLS; sing-vmess не менялся.

## Обновлённые fingerprints и REALITY

- Firefox обновлён с прежнего пресета до Firefox 148, Safari — до Safari 26.3
  по согласованному набору podkop-engine v1.14.2-r12.
- REALITY сохраняет X25519MLKEM768 key share, включая порядок hybrid/classical
  shares, и объявляет client version 26.3.27 вместо 1.8.1.
- Исправлен randomized: согласованы supported groups и key shares, ALPN
  присутствует для HTTP/2/gRPC. Random выбирает совместимые современные пресеты.
- Добавлены понятные сообщения для REALITY fingerprints без необходимого
  key share; android/360 отклоняются, edge/ios/qq сохраняются для старых серверов
  с предупреждением о совместимости новых серверов.

В отдельном сравнении этих оптимизаций с X 1.0.1 на 64 REALITY + Vision +
Firefox соединениях медианный RSS уменьшился примерно на 0,40 МиБ, после
одинакового GC — на 0,74 МиБ. Измерение выполнено до добавления XHTTP и
не является замером RAM итогового объединённого бинарника или обещанием
такой же экономии для любой нагрузки.

## Интеграция с Forkop

Для использования XHTTP требуются сопутствующие изменения Forkop:

- Runtime и UI определяют XHTTP по объявленной возможности ядра, независимо
  от признака Extended. Сам номер X не означает поддержку транспорта.
- Сохранено распознавание старых Extended/Extended compressed и вариантов
  без XHTTP — Tiny, обычного sing-box и прежних X.
- Кеш версии старого формата перепроверяется; интерфейс получает отдельную
  возможность sing_box_xhttp.
- Пользовательские фильтры подписки, включая белый флаг, сохраняются.

Эти изменения backend/LuCI поставляются пакетом Forkop, а не APK/IPK ядра.

## Сборка и компактность

- ARM64 aarch64_cortex-a53 и x86_64, APK/IPK и UPX binary archives.
- Upstream остаётся 1.14.2; Go 1.26.8 и UPX 5.2.1.
- Сохранены uTLS, Clash API, system TUN, WebSocket, HTTP и gRPC-lite.
- Графы обеих архитектур проверяются на отсутствие исключённых QUIC,
  Hysteria/Hysteria2/TUIC, gVisor и отдельного native management API.
- Исправлена APK staging-директория: упаковка на Linux filesystem сохраняет
  права каталогов, executable и metadata.
- Размер IPK payload вычисляется по содержимому самого пакета, без зависимости
  от оставшейся staging-директории.
- Авторство и GPL notices сохранены. Source archive содержит оригинальные
  патчи, их SHA-256 manifest, адаптеры, эффективные исходники и тесты.

Сравнение итогового проверенного кандидата 1.0.2 с опубликованным X 1.0.1:

| Архитектура | UPX X 1.0.1 | UPX проверенного кандидата | Прирост |
|---|---:|---:|---:|
| x86_64 | 9 863 528 Б | 9 938 872 Б | 75 344 Б — 73,6 КиБ, около 0,76% |
| ARM64 | 8 537 372 Б | 8 602 308 Б | 64 936 Б — 63,4 КиБ, около 0,76% |

Рост извлечённого package payload соответствует росту бинарника.
Размер executable после UPX-декомпрессии в RAM не считается расходом flash.

## Проверки

- Unit и race для изменённых пакетов, XHTTP и сохранённых транспортов.
- Проверены ошибки параметров/запросов, отмена, Close, deadlines, reset,
  восстановление соединений, churn и освобождение сессий.
- Матрица из 22 успешных сочетаний HTTP/1.1/HTTP/2, режимов, TLS/REALITY
  и отдельной download-ветви на контролируемом Xray.
- Существующие OpenWrt 24/25 x86_64 VM: start/restart, DNS, Clash API,
  JSON/SRS, повреждённые списки и сохранение последнего исправного кеша.
- Физический ARM64 GL-MT6000: start/restart, DNS, HTTPS, Clash API,
  текущая конфигурация с девятью ruleset и маршрутизация по JSON/SRS-спискам.
- Реальная подписка: 61 сервер — 58 TCP REALITY, один gRPC REALITY и два XHTTP
  TLS. Три прохода URLTest на x86_64 и отдельно три на ARM64 дали по 183/183
  успешных результата на каждой платформе.
- Оба XHTTP сервера дополнительно прошли HTTPS-запросы с ответами 204/200.
- После переноса новых fingerprints unit/race и обе сборки повторены;
  текущая подписка прошла 61/61 на OpenWrt VM и 61/61 на физическом ARM64 роутере.
  Более ранняя матрица из 22 сочетаний проверяла XHTTP до обновления fingerprints.
- По просьбе владельца итоговый кандидат 1.0.2-r1 оставлен на ARM64 роутере:
  пакетное обновление с 1.0.1-r1 прошло, DNS/Clash API/HTTPS работают.
  На VM использовался отдельный процесс без замены установленного пакета.

## Ограничения

- HTTP/3 и QUIC-транспорты отсутствуют намеренно.
- До обновления fingerprints контролируемый стенд Xray 26.9.x не проходил
  REALITY. Перенесённые изменения исправляют старый ClientHello/client version;
  после них повторена проверка текущей подписки, а не всей серверной матрицы.
  Совместимость всех параметров новых REALITY серверов не заявляется.
- Проверка доступности не является длительным нагрузочным тестом или
  гарантией обхода блокировок конкретной LTE сети.
